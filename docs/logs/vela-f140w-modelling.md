## Design checkpoints (criteria awaiting approval)

- **DC-1 — Run: vela22, single-Sersic source, curvature-adaptive quadrature, MAP → MCLMC
  (8 chains, 5000 + 5000).** Config `experiments/vela_f140w_v3/fit_sersic_vela22.yaml`; code
  GIGALens-Code branch `worktree-vela-generator-v2`, gigalens `linusu-dev-merge` (38152dc + PR #128); seed 0; shard 6/10 (= vela22 in manifest order).
  - **Claim type:** two links. (i) *Stochastic-estimator behaviour*: the truth-free pipeline
    (multi-start MAP from prior draws → diagonal qz → MCLMC) converges on this posterior.
    (ii) *Distributional claim*: a single Sersic source is a misspecified model for the vela22
    galaxy at Foundry depth, and the misspecification is visible in the residuals and biases the
    lens-mass posterior. Only (i) is graded by convergence metrics; (ii) by residual plots and
    the mass z-scores. Untested by this run: source recovery (no truth counterpart for Sersic
    parameters; the evaluation-truth rule for reconstructions applies to pixelated models later).
  - **Cause hypothesis:** the 20-parameter smooth model on a SNR-100 system has an essentially
    unimodal posterior reachable by MAP, so MCLMC will converge; the VELA source carries
    structure (nuclear cusp, asymmetry, clumps) at 10–30% of the arc brightness, which a Sersic
    cannot absorb, so the arc residuals will be several σ per pixel and coherent, and the lens
    slope/ellipticity/shear will move to compensate.
  - **Prediction (direction + magnitude):** max R-hat < 1.01, min ESS ≫ n_chains (hundreds+);
    χ²/ν in 1.2–3 (an excess of order 10³–10⁴ over the 25,600 pixels, i.e. a few hundred arc
    pixels at 2–5σ); θ_E recovered to ~1–2% (Einstein radius is robust to source shape);
    at least one of γ, e1, e2, γ1, γ2 with |z| > 3 (posterior-σ units), i.e. a
    misspecification bias much larger than the statistical error at this SNR.
  - **Falsifiers:** (i) max R-hat > 1.1 or min ESS ≲ 8 (≈ n_chains) → sampling failure; do NOT
    read (ii) from such a run; go to `/diagnose-sampling` (trace plots and MAP/init first, AP-1).
    (ii) χ²/ν ≈ 1 with unstructured residuals along the arcs → the VELA source is effectively a
    Sersic at this depth and the "misspecification" framing is wrong; or all mass |z| < 2 →
    Sersic misspecification does not bias the lens on this system.
  - **Metric + derived thresholds:** worst-parameter R-hat < 1.01 and min ESS: both from
    `docs/inference-diagnostics.md` (R-hat "at least below 1.1, ideally 1.01"; ESS ≈ n_chains
    = failure). χ²/ν: ν = 25,600 − 20, so the noise-only expectation is 1.000 ± 0.009 (√(2/ν));
    anything above 1.05 is a > 5σ excess and structurally not noise. z-scores use the posterior
    σ; |z| > 3 is the usual "bias ≫ statistical error" line and, with the mass posterior widths
    expected at SNR 100 (θ_E to ~0.3%), is far beyond run-to-run scatter.
  - **Blind spot:** R-hat/ESS cannot see all eight chains agreeing on the same wrong mode (the
    500-start MAP is the guard, not the sampler); χ²/ν cannot separate source misspecification
    from the two known quadrature residues (0.5σ at the lens-centre pixel, the 0.05σ arc
    floor), which is why the residual IMAGE, not the number, decides (ii).
  - **Expected appearance:** normalised-residual image with coherent ±3–5σ structure along the
    ring and at the source-centre images, clean sky and clean lens light; MCLMC traces
    stationary after burn-in with no chain segregation; the θ_E marginal narrow and near truth,
    γ/e/shear marginals displaced from truth by several widths.
  - **Cost:** one interactive node, 4× A100 80 GB, ≤ 4 h wall requested (`deepsrch_g`). Expected
    use well under an hour: MAP 500 starts × 500 steps on 45k evaluation points is minutes; MCLMC
    8 chains × 10,000 steps, 2 chains per GPU, is minutes to tens of minutes.
  - **Status:** approved by the user 2026-09-17 ("I approve DC-1. Go ahead and launch."); launched
    2026-09-17 via `run_vela22_sersic.sh` (gigalens linusu-dev-merge 09f92b4 = #115 + #128).

- **2026-09-17 — Fit prepared: vela22, Sersic source, adaptive quadrature (UNCERTIFIED, not run).**
  User decisions: Sersic source with broad priors (R, n, disk ellipticity), curvature-adaptive
  supersampling with the map shown before running, stock MAP → MCLMC with 5000 burn-in + 5000
  results, one 4-GPU interactive node. Built:
  - `epl_shear_sersic_sersic_source_broad` builder (`vela_sersic_source.py`): shared Vela lens
    priors; source R_sersic LogNormal(median 0.3", σ_log 0.8), n_sersic U(0.5, 8),
    (e1, e2) `TruncatedDiskNormal(e_max 0.8, scale 0.4)`, centre N(0, 0.5") per axis, lstsq
    amplitudes; optional `adaptive:` block → `AdaptiveImageData` with the config's uniform
    supersample forced to 1.
  - `map_mclmc` pipeline (`pipelines.py`): MAPStage (500 × 500) → `BridgeStage` diagonal qz
    (std 0.01 in z) → MCLMCStage. The repo's stock Vela pipeline `map_bootstrap_mclmc` pins the
    lens to truth and starts the chains at truth, so it is unusable for a truth-free fit.
  - Campaign `fit_sersic_vela22.yaml` (dataset block identical to `campaign.yaml`; sweep label
    `fit: sersic_v1` → run dir `runs/<sid>/fitsersic_v1`), launcher `run_vela22_sersic.sh`
    (salloc --no-shell, `srun --overlap` one process with 4 GPUs; MCLMC shards chains over
    devices, MAP shards its start batch).
  - CPU smoke test of the full wiring (tiny MAP/MCLMC): passes; model card prints
    `AdaptiveImageData … supersample=1 … n_points=44959`, PSF present (bin-first), noise
    0.0076/0.0085/0.086 min/med/max. The card's `info mixed-free-param-dtypes` (float32 Vela
    lens priors from python floats + float64 source priors) pre-exists in the Vela builders;

- **2026-09-17 — Quadrature checks for the vela22 map (`fit_checks/`, UNCERTIFIED).** Falsifier
  from the adaptive module's own docs: max |render − reference|/σ ≤ 0.1 per pixel.
  1. *Driver inputs.* `estimate_psf_sigma` on the 33 px STDPSF kernel gives 2.83 px (moment
     inflated by the wings), 2.5× the core width 1.126 px (FWHM 0.1723"/0.065"/2.3548). The
     moment value under-corrects the finest LoG scale (C = 1.26 instead of 3.05) and leaves arc
     pixels a tier low; the fit uses the core width. `nsig 3` (default) leaves isolated
     factor-2 spots on the sky (the documented gate leak); `nsig 4` cleans it.
  2. *Smooth Sersic fiducials* (true lens + true lens light + Sersic source at the true source
     position, lensed flux scaled to vela22's 418 cps, reference uniform ss = 32, `vela22_map_check_sersic.py`):

     | source | uniform ss=4 | adaptive, max 4 | adaptive, max 8 |
     |---|---|---|---|
     | n=1, R=0.2" | 0.26σ (lens centre) | 0.26σ (lens centre); ≤0.04σ elsewhere | 0.46σ (lens centre); ≤0.03σ elsewhere |
     | n=4, R=0.2" | **2.3σ** at the source-centre image | **2.3σ** | 0.46σ (lens centre); ≤0.03σ on the images |
     | n=4, R=0.1" | **5.9σ** | **5.9σ** | 0.46σ (lens centre); ≤0.05σ on the images |

     Finding: the dataset's declared uniform `inference_supersample: 4` is NOT adequate for
     cuspy Sersic sources (n ≥ 4, R ≤ 0.2") on these data — 2–6σ per pixel at the image of the
     source centre — and neither is the adaptive map capped at 4. Cap 8 fixes it at 45k points
     (11% of uniform ss=4). Decision: `max_factor: 8`.
  3. *Lens-centre pixel* (n = 5.17, R = 1.38" Sersic; `vela22_cusp_conv.py`, lens light only vs
     uniform ss=64): the midpoint quadrature of the cusp converges non-monotonically:
     ss=4 −0.19σ, 8 −0.50σ, 16 −0.15σ, 32 −0.035σ. The adaptive tier-8 render equals uniform
     ss=8 to 1e-12, so this is the cusp, not the grid. One pixel, source-independent, χ²
     contribution 0.25: accepted. (The generator's ss=32 truth is good to 0.035σ there.)
  4. *True VELA sky on the map* (`vela22_map_check.py`, reference = the ss=32 noiseless truth):
     0.42σ speckle along the arcs at every setting (raw Sunrise cell texture, sub-PSF, invisible
     to the data-driven driver; Σd² = 15 over 25,600 px). Irrelevant to a Sersic fit (the model
     is smooth; the data are the data) but it IS the relevant number for any future
     pixelated/flexible source that reproduces the texture.
  Final map (`vela22_curv_map_max8.png`): 44,959 points; tiers 1/4: 3552 px, 1/2: 6904, 1: 13,743,
  2: 165, 4: 1052, 8: 184 (lens centre + two ring knots); the counter-image stays native and
  renders within 0.02σ for every fiducial (it is the demagnified image).
